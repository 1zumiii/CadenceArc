# 运行时调试器

[返回首页](../README.zh-CN.md)

调试器在 PIE 里实时显示解析器的图和状态，并列出每一次调用的结果。它在可选的 `CadenceArcEditor` 模块里（`Type=Editor`），打包的游戏不包含它。

打开方式：**Tools > Debug** 下的 **Arc Debugger** 和 **Arc History** 两个标签页。两者都只读：不调用会改变状态的解析器 API，不写图资产，运行时也不回调它们。

## Arc Debugger

在下拉框里选一个 PIE 里的解析器（显示为 `Actor @ World`），图和状态每帧刷新。

![Root 上按住 Heavy 时的 Arc Debugger](Images/arc-debugger-hold.png)

*在 `Root` 按住 Heavy。两条 `Released` 边是预备边，虚线随蓄力进度填充。`OpenerC` 的虚线框表示此刻松手会选中它。右侧时间轴标出按下、开始蓄力、满蓄和自动松手截止。*

### 图上的颜色

| 显示 | 含义 |
| --- | --- |
| 绿色标题栏 | 已提交的节点 |
| 黄色描边和黄色连线 | 等待 `Started` 的候选请求 |
| 橙色虚线边、进度填充 | 预备边：有按住资格时，这个 Tag 的 `Released` 边 |
| 橙色虚线框 | 此刻松手会选中的档位 |
| 亮色 / 正常 / 变暗 | 分支聚焦：下一步 / 之后还能走到 / 当前路径已经走不到 |
| 紫色描边 | Arc History 里选中的那条记录 |
| 虚线回边 | 往回跳的转移，从图下方绕回 |

![OpenerA 到 ChainA3 之后的分支聚焦](Images/arc-debugger-branch-focus.png)

*`OpenerA → ChainA3` 之后，请求正在执行，缓冲窗口打开。当前节点的下一步保持亮色，走不到的分支变暗。*

### 转移条件

端口行在输入后面接上条件和优先级，例如 `Heavy R [0.8, ∞) +Forward #1`：

| 写法 | 含义 |
| --- | --- |
| `+Forward` | `RequiredContextTags` 里的 Tag |
| `-Air` | `BlockedContextTags` 里的 Tag |
| `pause≥0.3s`、`pause<0.3s`、`pause 0.1–0.3s` | 停顿区间 |
| `#2` | 优先级，为 0 时不写 |

没有条件、优先级为 0 的边，文字和以前一样。按住时，“此刻松手会选中的档位”按当前的持久上下文过滤条件、取优先级最高的一条，打平时不标。带停顿区间的档位不参与这个预览，因为松手之前算不出停顿。

### 输入显示

画布左下角固定显示解析器收到的输入，类似格斗游戏训练模式的输入记录：

- 第一行是持久上下文和停顿。`Ready` 时显示距上次完成多久，例如 `pause 0.42s`；动作执行中提示缓冲输入的停顿按 0 算。
- 有按住资格时多一行：橙色键帽、蓄力阶段和按住时长。
- 最下面是最近 6 次输入，新的在左，组与组之间用竖线隔开。事件带的上下文画在键帽前面，读作 `[Forward] + [Light]`。松手的键帽带 `↑`，下面写按住时长。进了缓冲的键帽是蓝框，没起作用的是红框并标 `ignored`。
- 输入不会按时间消失，只会被新输入挤掉；超过 1.5 秒的逐渐变暗。

这里显示的是语义输入，不是物理按键。单按 W 移动不会出现键帽，方向只在按 Light、Heavy 时作为上下文附在那次输入上。物理按键属于宿主的输入系统，要显示请在宿主里做。

“距上次完成多久”和键帽的年龄，用的是宿主最近一次传给解析器的时间。宿主每帧调用 `AdvanceInputTime` 时，这个时间最多差一帧。

### 浏览

| 操作 | 效果 |
| --- | --- |
| **Follow**（默认打开） | 当前节点变化时，自动缩放（最小 0.6 倍）并滚动到能看见它和它的直接后继。放不下的后继在视图边缘显示可点击的提示。 |
| 右键或中键拖动 | 平移，会关掉 Follow |
| Ctrl + 滚轮 | 以鼠标为中心缩放（0.3 倍～2 倍），会关掉 Follow |
| 悬停节点 | 高亮它的连线 |
| 悬停连线 | 高亮两端，显示 `Source → Target · condition` |

### Layout 菜单

这些选项按用户记住，只改变绘制，从不修改资产。

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| Right-angle edges | 开 | 前向边只用水平和竖直线段。竖线在列间空隙里各占一条轨道，互不重叠。关闭后用光滑曲线，端点不变。 |
| Reorder ports to reduce crossings | 开 | 按出边去向重排节点里的端口行：前向边从上到下，然后是引用标签和坏目标、往回跳的边、自环。只改显示顺序，资产里的顺序和解析结果不变。 |
| Compact chains | 关 | 把一进一出的简单链纵向叠在一个分组框里，减少列数。 |
| References for long edges | 关 | 跨列不少于 N 的边不画长线，改为源节点旁的小标签（`→ SkillF`，往回跳为 `↩ Root`）和目标旁的一小段接入线。点标签跳到目标，点接入线跳回源节点。 |
| Input display | 开 | 在 Overlays 分组里。显示或隐藏左下角的输入显示。 |

### 布局算法

默认是确定性的分层布局（Sugiyama 风格）：

- 从入口深度优先遍历，找到的回边画成虚线，从图下方的通道绕回；
- 列号取最长路径，前向边一定指向右侧；
- 长边在经过的每一列预留一条通道，所有连线只走节点之间的空闲区域，不会压在无关节点上；
- 布局每帧根据资产重新生成，节点和转移的索引不变。

紧凑链用高度换宽度，只处理简单链，不会把任意分支区域重新分组。

## Arc History

Arc History 跟随 Arc Debugger 选中的解析器，按从新到旧列出调用。成功只显示一行；失败标红，下面是白话原因和枚举名，例如 `No transition for Heavy P from SkillD (NoMatchingTransition)`。

![同一次 PIE 的 Arc History](Images/arc-history.png)

*`~` 开头的时间借自解析器最近一次收到的宿主时间。#15 是一次被拒绝的按住，下面写着原因。*

按图选过边的记录，会在输入后面写出当时合并后的上下文，例如 `Light P [Forward] at Root → DashStrike`。选中的边看了停顿时，还会写出停顿时长。条件类的失败会逐条说明候选边差在哪：

- `ConditionNotMet`：例如 `No edge for Heavy P at SkillA fits: Dash needs Forward; HeavyB pause 0.10s, needs ≥0.25s. Context: Air, pause 0.10s`。
- `AmbiguousTransition`：列出在哪个优先级打平的边，并提示提高其中一条的优先级，或让条件互斥。

这些说明按当前资产里的边生成。PIE 中途改了图，说明可能和当时不一致。

- **Failures only**：只显示失败。
- **Clear**：隐藏已有的行，不停止记录。
- 选中一行：在图上用紫色描出对应的节点和边，并滚动过去。
- PIE 结束后保留已读到的行（标题显示 `(ended)`），换解析器时清空。

### 记录规则

- 只在 `WITH_EDITOR` 下存在。打包的游戏里没有记录代码，Development 打包也一样，所以打包后看不到历史。这是有意的：记录只服务于编辑器里的调试器。没有录制开关。
- 每个公开入口执行完业务逻辑后，往 256 条的环形缓冲（`GetDebugHistory()`）追加一条记录，满了覆盖最旧的。查询不记录。
- `AdvanceInputTime` 只在越过蓄力阶段、自动松手或被拒绝时记录，每帧的调用不会冲掉有用的记录。
- **失败**的定义：输入既没产出请求也没进缓冲、按住被拒、松手没选中招式、握手没返回 `Success`、重置或初始化失败、完成时缓冲被丢弃。完成时没有缓冲、完成时还有按住在等松手，都不算失败。
- 不带时间戳的调用（`Started`、窗口变化、握手）显示 `~` 加最近一次宿主时间。宿主每帧推进时间，所以最多差一帧。

## 在 Sandbox 里复现问题

Sandbox 的演示执行器有一组 **Debug Scenarios**：

| 选项 | 用途 |
| --- | --- |
| `TimeScale` | 拉长执行器的计时，方便看窗口 |
| `StartDelaySeconds` | 延迟开始，候选请求会停留在黄色状态 |
| `RejectEveryNthRequest` | 每 N 个请求拒绝一次 |
| `bSendStaleCallbacks` | 完成后再发一次过期回调 |

`TimeScale` 不影响图的 `MaxBufferedInputAgeSeconds`，所以会让缓冲的输入过期。要整体放慢，请用控制台命令 `slomo`。
